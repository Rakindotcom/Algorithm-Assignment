CORE ALGORITHMIC PARADIGMS

Algorithms & Data Structures Detailed Breakdown

A comprehensive explanation of each algorithmic component, detailing the core theoretical concept, the specific data structures employed, its role in the blood supply system, and an interactive demonstration.

MergeSort: Stable Priority Queue & Patient Fairness

Time: O(n log n) | Space: O(n)
Data Structure: Dynamic Array / FIFO Priority Buffer

1. Algorithm & Data Structure

MergeSort is a divide-and-conquer sorting algorithm. It recursively divides an array of requests into halves until arrays of size 1 remain, then merges them in sorted order. Data Structure: A dynamic array with an auxiliary merge buffer. The comparison operator preserves stability ($\le$), ensuring that identical keys retain their initial arrival sequence.

2. System Implementation & Use Case

In mass-casualty emergencies, simultaneous requests arrive from multiple hospitals. MergeSort ranks requests using a multi-factor medical composite score: Score = W_urgency + (5.5 × Severity) + (0.55 × min(WaitTime, 90)) + W_rarity Fairness Guarantee: Stability guarantees First-Come, First-Served fairness so that earlier-waiting patients are never starved of care by tie-breaking arbitrariness.

Dijkstra's Algorithm: Dynamic Travel Time vs. Physical Distance

Time: O((V + E) log V) | Space: O(V + E)
Data Structures: Binary Min-Heap & Adjacency List

1. Algorithm & Data Structure

Dijkstra’s algorithm finds the shortest path on a weighted graph $G(V, E)$ with non-negative edge weights. Data Structures: An Adjacency List representing intersections and road segments, paired with a Binary Min-Heap Priority Queue to extract the tentative minimum distance node in $O(\log V)$ time.

2. System Implementation & Use Case

Traditional GPS routing often targets minimum physical distance (kilometers). In emergency blood delivery, minutes matter directly for patient survival. Our system weights edges by dynamic travel time under live traffic. If an accident or road closure occurs, Dijkstra instantly relaxes alternative edges and reroutes vehicles through safe corridors.

Greedy Selection: Instant Dispatch for Crashing Emergency Cases

Time: O(n) | Space: O(1)
Data Structure: Linear Candidate Array & Direct Lookup

1. Algorithm & Data Structure

A greedy algorithm makes the locally optimal choice at each decision stage without backtracking. Data Structure: Evaluates candidates in a linear array, matching nearest available stock directly in $O(n)$ time.

2. System Implementation & Use Case

When a patient is in acute hemorrhagic shock (Level 10 Critical), waiting for a comprehensive multi-variable batch optimization cycle increases mortality risk. The greedy algorithm acts as an emergency triage bypass: it immediately commits the nearest available compatible blood unit to the crashing patient within milliseconds.

Dynamic Programming: 0/1 Knapsack Stock Allocation

Time: O(N × W) | Space: O(N × W)
Data Structure: 2D State Matrix (Memoization Table)

1. Algorithm & Data Structure

Dynamic Programming breaks an optimization problem into overlapping subproblems, recording optimal solutions in a table. Data Structure: A 2D State Matrix of dimensions $(N + 1) \times (W + 1)$, where $dp[i][w] = \max(dp[i-1][w], dp[i-1][w - \text{weight}_i] + \text{value}_i)$, paired with a backtracking array to reconstruct the selected set.

2. System Implementation & Use Case

Blood bank inventory and cold-chain vehicle fleet capacity are limited resources ($W$). Competing hospitals require different units and blood types ($w_i$), carrying varied clinical benefits ($v_i$). Our DP algorithm maximizes total medical benefit while prioritizing near-expiry stock (within 4 days) to minimize avoidable biological wastage.

Edmonds-Karp: Transportation Network Capacity Verification

Time: O(V · E²) | Space: O(V + E)
Data Structures: Residual Capacity Graph & BFS Queue

1. Algorithm & Data Structure

Edmonds-Karp computes the maximum flow through a network using the Ford-Fulkerson method. Data Structures: A Residual Graph tracking remaining forward and backward capacities, coupled with a FIFO Queue to find the shortest augmenting path using Breadth-First Search (BFS).

2. System Implementation & Use Case

An allocation might look optimal in theory, but can the physical roads and delivery vehicles physically transport that volume without causing gridlock? Edmonds-Karp verifies feasible flow across the city road network, detecting saturated bottleneck corridors and ensuring delivery plans do not exceed physical transport limits.

WASHINGTON ACCORD COMPLEXITY JUSTIFICATION

Why This Qualifies as a Complex Engineering Problem

Formal verification of Washington Accord criteria P1 through P7, demonstrating multi-faceted engineering complexity far beyond isolated textbook exercises.

P1

Depth of Knowledge

Requires advanced graph theory, network flow algorithms, 2D dynamic programming, and clinical priority modeling—not solvable by any single textbook algorithm.

P2

Conflicting Requirements

Must continuously balance delivery speed vs. fairness vs. expiry wastage vs. critical emergency coverage. Improving one directly degrades another.

P3

Depth of Analysis

Demand, supply, road congestion, blood expiry, and patient clinical severities all fluctuate dynamically in real time without obvious closed-form solutions.

P4

Unfamiliarity & Scope

Transcends isolated classroom assignments by coupling live urban transit topology with strict biological donor-recipient compatibility and cold-chain fleets.

P5

Applicable Codes & Standards

Incorporate clinical blood safety guidelines, refrigerated cold-chain standards, and hospital trauma response protocols into algorithmic constraints.

P6

Diverse Stakeholders

Resolves conflicting priorities between central blood banks, emergency room trauma surgeons, ambulance dispatchers, and health authorities.

P7

Interdependence of Sub-problems

The 5 stages are tightly coupled: a traffic delay (Dijkstra) alters delivery ETA → changes request urgency (MergeSort) → shifts inventory utility (DP) → changes feasible bottleneck throughput (Edmonds-Karp). No component can run in isolation.
